# PEG parser generator

This is an implementation of Python's PEG parser generator 'pegen',
modified so that it generates a parser and in Java rather than C,
including the AST node classes in place of C `struct`s.

It is based on [Pegen2](https://github.com/Tobias-Kohn/Pegen2)
by Tobias Kohn,
which is itself an adaptation to Java of the original work in
[CPython](https://github.com/python/cpython).

Quite large chunks of the parser generator are unmodified from the
corresponding modules in CPython (taken originally from version 3.9).
Since the files do not contain any evidence of their origins,
we acknowledge that fact here,
rather than modify them just for that purpose,
in the interests of easy comparability.

By borrowing heavily in our parser from CPython's,
the reference implementation,
we hope to keep up with the subsequent evolution of the Python
language itself.


## Generating Java

In its present context, as part of Jython,
the parser generator will be invoked from the Gradle build,
and deliver generated classes into `~/build/generated/sources/...`
where `~` represents the root of the current Gradle *sub-project*.
The generated tokeniser, parser and AST classes
depend on elements of the hand-written code base
found in `~/src/main/java/...`.

The packages are same in both places.
The AST nodes are in `... .internal.ast`,
and the parser is in `... .parser`.

You *can* invoke the programs at the command prompt if you want.
For this to work,
the PYTHONPATH environment variable must include
the (relative) path of the project's Python tools
`~/tools/python/lib`.

There are three scripts that may be used as commands
to generate the sources of the tokenizer, the AST, and the parser.
Note that the script `generate_token_java.py`
depends on `generate_token.py` copied from CPython's
`Tools/scripts/generate_token.py` from tag v3.11.9 at the time
of this writing.
They are used in the following order (from the project root):
```
$ python tools/python/generate_token_java.py
$ python tools/python/asdl_java.py
$ python -m pegen java tool/python/grammar/python.gram
```
Each command takes arguments you may discover by giving the `-h` option.

By default,
generated classes are delivered to a directory `./generated`,
relative to your working directory.
The default package name for the AST classes
is `org.python.internal.ast`.
These are generated by `asdl_java`.
`pegen.__main__` generates the parser
`org.python.parser.GeneratedParser`,
and some more classes in the AST package.

Supporting classes in those packages, not generated by these commands,
appear in the source tree of this project and
must be merged with the generated classes in any practical build.
The putative AST and parser classes also depend on the Jython core classes
assumed to be at `org.python.objects`
for which placeholders are provided in the project.

It ought then to be possible to compile the AST nodes and parser with:
```
$ javac -d classes -sourcepath generated:java/src generated/org/python/parser/GeneratedParser.java
```
and get the compiled classes in `./classes`.
At the time of writing,
the generated and support Java code does not compile as a joint code base
without error because of inconsistencies in code generation.


## AST-Visitors

There are separate interfaces for the different classes of AST types: statements,
expressions, etc.  If you want to only handle expressions, for instance, you can
thus implement the `ASTExprVisitor`-interface with the expression-related
methods only.  On the other hand, you can also go for the `DefaultASTVisitor`-class
that implements all interfaces.


## Structure

The overall project contains a number of different parts.  The *tokenizer* has
been translated to Java manually, as the tokenizer remains very stable across
versions and hardly ever changes.  The *AST* is generated from the ASDL directly,
as is the *parser*.  In order to translate the actions embedded in the parser
from C to Java, we also include a simple *C parser*.

- **`ASDL`**:  this is the description of the AST itself and how the different AST
  nodes relate to each other.  Look for the `asdl_java.py` file that extends the
  existing ASDL->AST generator so as to generate Java classes.
- **`cparser`**:  a simple parser for a subset of C that is used to parse some header 
  files and the actions inside the grammar that are written in C.  The readon for
  parsing the header files are primarily the macros that are then used in the actions
  and that change from time to time.  In the long run we probably want to use a
  more stable project such as 
  [Eli Bendersky's C-parser in Python](https://github.com/eliben/pycparser).
- **`pegen`**:  this contains the parser generator.  Look for the `java_generator.py`
  file, which is our extension to generate Java code.  It also requires the
  _action-translator_ found in `action_translator.py`, which makes use of the
  `cparser` mentioned above.
- **`src/org/python`**:  on the one hand, this is where the generated Java files go,
  i.e. the AST as well as the parser.  On the other hand, this also contains the
  hand-written Tokenizer, Tokens, etc.

The information flow amongst several of these elements is depicted in
[A Visual Guide to Source Generation](doc/generation.md).
If you are interested in navigating the Pegen2 code,
and relating it to that in CPython,
[A Survey of the Modules](doc/modules.md) is intended to help.
